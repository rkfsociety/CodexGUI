# Codex feature parity

Status: in progress. Objective: match Codex desktop workflows supported by Codex CLI and app-server without requiring users to install the CLI package for normal work. The active goal authorizes version changes and release publication after validation.

Official baseline: [Codex app overview](https://openai.com/index/introducing-the-codex-app/) documents isolated worktrees, review/comment workflows, skills, and scheduled automations. [OpenAI's App Server architecture](https://openai.com/index/unlocking-the-codex-harness/) describes the shared harness and the client protocol for persistent threads, turns, tool events, approvals, and review.

Completed and published on `main`: pre-window update check and install (`0.0.010`); per-chat managed worktrees.

Current branch: `codex/app-parity-thread-fork`. Thread context-menu forks use app-server `thread/fork`; a real saved session was forked into a temporary Git worktree using its `cwd` override, then both test artifacts were cleaned. The existing uncommitted review action now uses app-server `review/start`; its full review turn still needs end-to-end verification. The branch also includes per-file diff viewing and selected diff context in the prompt.

Version is `0.0.015`. Normal turns, review, thread history, model discovery, ChatGPT device-code sign-in, and worktree forks use the standalone official App Server runtime `0.163.0`, downloaded and SHA-256 verified on first launch. The worker persists streamed events and control requests so turns can survive closing the window, handle command/file-change approvals, interrupt, and steer. Worktrees use Git and app-server `thread/fork`. Local verification passed: `dotnet build --no-restore`; package SHA/layout check; standalone server `initialize` and `model/list`; model-catalog parsing; account-state reading; paginated history reading; Git worktree create/register; app-server fork into a worktree; fake-server approval, steer, and interrupt flow. UI-driven approval/steer/interrupt, device-code login, and app-server `review/start` remain unverified. CLI is still used for plugin marketplace management and recovery of pre-`0.0.015` runs. The standalone App Server binary is pinned to the client; the generic CLI `app-server` command is labeled experimental by upstream docs.

Known gaps: syntax-highlighted, line-anchored review comments; scheduled automations; a browsable multi-agent/subagent workflow; plugin marketplace management without CLI; and interactive `item/permissions/requestApproval`, `mcpServer/elicitation/request`, and `tool/requestUserInput` server requests, which the current client reports as unsupported. Keep interim work on a feature branch; publish the verified final release to `main` when parity is ready.
