## Official capability comparison (2026-10-22)

The reviewed baseline is defined by the official [Codex developer guides](https://learn.chatgpt.com/docs/developers), [App Server reference](https://learn.chatgpt.com/docs/app-server), [local environments guide](https://learn.chatgpt.com/docs/environments/local-environment), [scheduled tasks guide](https://learn.chatgpt.com/docs/automations), [code review guide](https://learn.chatgpt.com/docs/code-review), [browser extension guide](https://learn.chatgpt.com/docs/chrome-extension), and [CLI command reference](https://learn.chatgpt.com/docs/cli/reference).

Covered in CodexGUI: local App Server chats and permissions, model selection, history/fork/archive/delete, prompt queue/steer/interrupt, managed Git worktrees, file-level and hunk-level stage/unstage, hunk and file restore, confirmed untracked cleanup, staged commits and branch push, per-thread goals, diff review and comment drafts, chat search, multi-agent browsing, skills, interactive PowerShell tabs, updater, and local minute-interval, daily/weekly/monthly, and RRULE schedules across projects. Standalone tasks fan out to one run per selected project; existing-thread continuation is limited to one project.

Known parity gaps:
- Git UI supports stage/unstage all or individual files and supported text diff-hunks, tracked-file restore, previewed untracked cleanup, staged commits, branch publish and push. Pull-request creation remains a gap.
- Local environments lack project setup scripts for new worktrees and reusable named actions in the toolbar.
- Scheduling now accepts RFC 5545 RRULEs with FREQ, INTERVAL, COUNT, UNTIL, BYxxx and WKST, plus multi-project standalone runs. Known differences: leap-second BYSECOND=60 is unsupported; period/candidate expansion is bounded; if a worker is still busy, missed recurrence slots are coalesced into a single catch-up run.
- CodexGUI has a pinned sidebar section stored in local state; pin state is not shared with other clients because the pinned App Server `0.163.0` metadata-update schema has no `isPinned` field. The Activity window lists active, waiting-for-input, and unread chats and opens a selected chat. A detailed activity event timeline remains a gap; background completion uses a tray notification and persisted unread marker.
- There is no app/connector directory browser; configured MCP servers work, but the app does not offer the official app/connector discovery and management UI.
- There is no in-app browser or browser-extension tab/context handoff.
- CodexGUI's normal chat/runtime path does not require the Codex CLI package: it downloads the pinned standalone App Server binary, matching the official desktop/IDE client architecture. The pinned protocol has stable `marketplace/add`, `marketplace/remove`, and `marketplace/upgrade` methods. The current official App Server reference still labels `plugin/list`, `plugin/read`, `plugin/install`, and `plugin/uninstall` as under development, so the Extensions window keeps its optional CLI-backed catalog/list/install path until those RPCs are production-ready. The CLI fallback for development and recovery of legacy runs is also optional.
- The integrated terminal does not render full-screen VT applications.
- Cloud environment publishing and remote/cloud tasks are not implemented; they are a separate execution surface from the local App Server and need an explicit backend/API audit.

Keep all repository work on `main`. Publish verified releases to `main` after checking the version and release workflow effects.
