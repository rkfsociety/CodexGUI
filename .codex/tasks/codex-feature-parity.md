# Codex feature parity

Status: in progress. Objective: match Codex desktop workflows supported by the installed Codex CLI and app-server. The active goal authorizes updating declared requirements and publishing the final release after validation.

Completed and published on `main`: pre-window update check and install (`0.0.010`); per-chat managed worktrees.

Current branch: `codex/app-parity-thread-fork`. This branch adds a context-menu action that forks a persisted Codex session through app-server `thread/fork`, restores the copied history, and preserves the source chat. The installed app-server schema includes `ThreadForkParams` and `ThreadForkResponse`. A protocol smoke check confirmed `thread/fork` is registered and rejects a nonexistent ID as expected; a successful fork of a real session still needs end-to-end verification. The branch also adds review of uncommitted changes via `codex review --uncommitted`, a per-file diff viewer, and selected diff context in the prompt; build passed, runtime review behavior is unverified.

Normal new and resumed chat turns now use the bidirectional app-server protocol in a detached CodexGUI worker. The worker persists streamed events and controls so the UI can reconnect after closing, answer command/file-change approvals, interrupt a turn, or steer it; published workers run from a versioned local runtime cache so they do not lock the install directory during self-update. Managed-worktree bootstrap still uses `codex exec`. Version is `0.0.014`. `dotnet build --no-restore` passed, an app-server smoke check succeeded for `initialize` and `model/list`, and the detached worker startup/error persistence path passed a local smoke check. UI-driven approval/steer/interrupt and a successful real `thread/fork` remain unverified. CodexGUI still requires the installed `codex.exe` runtime; it does not launch the CLI TUI for normal chat. Official docs identify app-server as the rich-client interface, but currently label its CLI command experimental.

Known gaps to investigate against current official Codex features: syntax-highlighted, line-anchored review comments; scheduled automations; and broader multi-agent workflows. Decide whether to bundle a matching Codex runtime so users do not separately install the CLI package. Keep interim feature work on a non-main branch; publish the verified final release to `main` when the parity goal is ready.
