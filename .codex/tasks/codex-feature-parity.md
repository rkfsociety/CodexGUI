# Codex feature parity

Status: in progress. Objective: match Codex desktop workflows supported by Codex CLI and app-server without requiring users to install the CLI package for normal work. The active goal authorizes version changes and release publication after validation.

Official baseline: [Codex app overview](https://openai.com/index/introducing-the-codex-app/) documents isolated worktrees, review/comment workflows, skills, and scheduled automations. [OpenAI's App Server architecture](https://openai.com/index/unlocking-the-codex-harness/) describes the shared harness and the client protocol for persistent threads, turns, tool events, approvals, and review.

Completed and published on `main`: pre-window update check and install (`0.0.010`); per-chat managed worktrees.

Current branch: `codex/app-parity-thread-fork`. Thread context-menu forks use app-server `thread/fork`; a real saved session was forked into a temporary Git worktree using its `cwd` override, then both test artifacts were cleaned. Review uses app-server `review/start`; its full review turn still needs end-to-end verification. The branch also includes per-file diff viewing and selected diff context in the prompt.

Version is `0.0.017`. Normal turns, review, thread history, model discovery, ChatGPT device-code sign-in, worktree forks, and scheduled automations use the standalone official App Server runtime `0.163.0`, downloaded and SHA-256 verified on first launch. Automation definitions and run review records persist in LocalAppData; a 30-second local scheduler runs while CodexGUI is open, and launched turns use the detached worker. Unattended runs use `approvalPolicy=never` with `workspaceWrite` and sandbox network disabled; configured MCP integrations remain available. Git worktree isolation is enabled by default. Existing verification through `0.0.016` remains recorded in Git history. For `0.0.017`, `dotnet build --no-restore` passes with zero warnings and errors, `WorkspaceView.xaml` parses as XML, and reflection-based checks cover daily/weekly next-run calculations and invalid cadence rejection. UI-driven schedule editing, a live scheduled run, and restoration after closing/reopening the app have not been exercised. UI-driven approval/steer/interrupt, device-code login, app-server `review/start`, and subagent navigation also remain unverified. CLI is still used for plugin marketplace management and recovery of pre-`0.0.015` runs. The standalone App Server binary is pinned to the client; the generic CLI `app-server` command is labeled experimental by upstream docs.

Known gaps: syntax highlighting and native per-comment threads in the diff reviewer; fuller multi-agent browsing beyond opening a reported subagent thread; plugin marketplace management without CLI; and interactive `item/permissions/requestApproval`, `mcpServer/elicitation/request`, and `tool/requestUserInput` server requests, which the current client reports as unsupported. Keep interim work on a feature branch; publish the verified final release to `main` when parity is ready.
