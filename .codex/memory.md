# CodexGUI working memory

- `App.xaml.cs` handles startup, user installation, single-instance activation, app updates, App Server runtime setup, and first-run ChatGPT device-code login. `Infrastructure/Updates/AppUpdater.cs` verifies downloaded release archives and signatures.
- `MainWindow.xaml.cs` owns chat/project state, request queues, repository context, and the UI event loop; state persistence is in `MainWindow.State.cs`, and scheduling/run reconciliation is in `MainWindow.Automations.cs`. `Views/WorkspaceView.xaml` is the hot-reloaded layout.
- Ctrl+F searches chat titles; an option also searches loaded user and assistant messages in the open chat and scrolls the selected match into view.
- `CodexWindowTheme` applies the shared WPF window palette, font, and dark caption; `CodexMessageDialog` replaces system `MessageBox` calls, and `CodexFilePickerWindow` handles file opening, folder selection, and screenshot saving in the dark theme. `Scripts/Capture-WorkspacePreview.ps1` renders workspace XAML with preview conversation fixtures, the shared `ChatWelcomeView`, or built Activity, Actions, their prompt/command action editor, marketplace-add and marketplace-manager, file picker, Pull Request, automation editor, and worktree setup windows to PNG without starting CodexGUI. Its Calendar view checks the shared dark Calendar template. Fresh unsaved chats show the shared welcome view and start suggestions; saved empty chats retain their title and omit the suggestions.
- Composer model, effort, worktree, and access controls share the `ComposerControlButton` style, 34-pixel height, centered labels, spacing, and vector chevrons in `Views/WorkspaceView.xaml`; worktree and access symbols are vector paths whose color follows their active state. App-wide `ComboBox`, `ComboBoxItem`, `ListBoxItem`, `CheckBox`, DatePicker, Calendar, and ScrollBar visuals are defined in `App.xaml`. Its shared `ScrollViewer` template explicitly applies `CodexScrollBar` to both axes, including text fields and lists; zero scrollbar minimum dimensions override the system theme's 17-pixel minimum. The Codex brand label is not a dropdown.
- `Views/WorkspaceView.xaml` keeps the 42-pixel `SidebarIconRail` visible beside the collapsible project/chat panel. Its icon buttons open the existing chat, search, activity, automation, subagent, extensions, MCP, repository-context, and Actions features. `ToggleSidebar` collapses only the 280-pixel panel and can override responsive auto-hide when the context panel is open in a narrow window; `MainWindow.UpdatePanelLayout` expects four root columns.
- `UI/Chat/ChatMarkdownRenderer.cs` formats finalized assistant replies with headings, lists, tables, emphasis, code, and explicit HTTP/HTTPS links; active streaming keeps its plain TextBlock so chunks can be appended without reparsing the whole message.
- Conversation scrolling follows new content only when the same thread is already within 72 pixels of the bottom; rerendering preserves the reader's prior offset, and switching threads opens at the latest message.
- Consecutive Codex activity items such as reasoning, commands, tool calls, and file changes render in one collapsed expander; opening it shows per-item details and subagent links.
- Live assistant text is coalesced at 80 ms intervals and appended to the active `TextBlock` as inline runs; activity-triggered conversation rebuilds use the same cadence to keep composer input responsive.
- Composer files and images are held separately from `PromptInput` and shown as removable previews (image thumbnails or file names). User message bubbles split the same attachment suffix into previews instead of displaying raw paths; `MainWindow.CreateAttachmentPreview` loads bounded thumbnails without holding file handles and falls back to the file name with an error tooltip. Clipboard paste, file selection, and screenshot capture add to this list; `SendPromptAsync` serializes each path as a `Файл для контекста: <path>` line before queueing or steering so queued and recovered prompts retain their attachments. Queued prompts can be edited before processing; the editor separates those path lines from message text and preserves attachment chips when saving.
- `PromptInput` uses WPF's system spell checker for user-entered text and follows the active Windows input language; the placeholder text keeps spell checking disabled so it does not show red misspelling marks.
- Chat goals are persisted by App Server `thread/goal/*` methods in thread history. `AppServer/CodexAppServerClient.cs` supplies user-origin get/set/clear calls. `MainWindow.xaml.cs` loads the selected session goal for display, refreshes it when switching back to a chat, shows status and a truncated objective on the composer button, keeps the full objective in the tooltip, and re-reads the server value before editing. A new chat can hold a persisted CodexGUI-local `PendingGoal`; the detached worker applies it with `thread/goal/set` after thread creation and before `turn/start`, then clears the local draft when the success event is processed.
- `Git/GitRepositoryInspector.cs` reads status and separate staged/unstaged diffs, then performs file/hunk stage, unstage and restore plus untracked cleanup, commit, and branch push actions. The chat overview card is inside the chat at top right; its `+ / −` totals compare the full working tree, including untracked text files, to the upstream merge base, falling back to `origin/HEAD` when no upstream is configured. It shows dashes when no comparison base is available. The diff reviewer exposes stage/revert for unstaged text hunks and unstage for staged text hunks. The repository panel only offers these mutations when no Codex run is active; file restore, unstaged-hunk revert, and untracked cleanup prompt before discarding changes. Cleanup previews and removes only non-ignored untracked paths. In an unborn repository, unstaging uses `git rm --cached` so files stay in the working tree.
- `Git/GitHubPullRequestService.cs` uses optional GitHub CLI to create a PR only for a clean, already-published GitHub.com branch; `--head` prevents the PR command from pushing the branch.
- `UI/Windows/DiffReviewerWindow.cs` renders syntax-colored diff paragraphs, maps selections back to old/new hunk line numbers, and groups comments with replies. Comment drafts become chat context only when the user attaches them to the composer.
- Multi-agent activity uses App Server `collabToolCall` items. Read `receiverThreadIds` and `agentsStates` rather than assuming a single `newThreadId`; `UI/Windows/CodexSubagentsWindow.cs` aggregates current-thread events and opens a child thread's full history.
- `UI/Windows/CodexTerminalWindow.cs` hosts PowerShell tabs via `AppServer/CodexAppServerTerminalHost.cs`. On Windows, streaming `command/exec` is unavailable in the workspace sandbox; opening a terminal outside Full Access mode requires an explicit per-window consent prompt.
- Normal chat turns and worktree forks run through `CodexAppServerTurnWorker` in a detached CodexGUI child process; file-backed JSONL output and control files under `%LOCALAPPDATA%\CodexGUI\workers\<runId>` preserve reattach, approvals, stop, and steer. Published workers run from a versioned copy under `%LOCALAPPDATA%\CodexGUI\worker-runtimes` so app updates can replace the install directory. `Scripts/CodexCliWorker.ps1` remains to recover legacy CLI runs saved by older app versions.
- `AppServer/CodexAppServerClient.cs` starts short-lived app-server processes for request/response calls; `AppServer/CodexAppServerTurnWorker.cs` handles bidirectional streamed turns and server-initiated requests. Released builds use the downloaded `codex-app-server.exe`; development can fall back to `codex.exe app-server`.
- Released builds download the pinned `codex-app-server` Windows package on first launch; `AppServer/CodexAppServerRuntime.cs` owns its version, archive digest, extraction checks, and runtime path. Normal chats do not require the Codex CLI package. `CodexCliService` remains optional for the extension plugin catalog/list/install UI; `ExtensionsWindow` adds, refreshes, and removes Git marketplaces via stable App Server RPCs; `CodexMarketplaceCatalog` reads the source list through the optional CLI. `Scripts/CodexCliWorker.ps1` recovers legacy runs.
- The MCP server status window reads global server state through stable App Server `mcpServerStatus/list` with `toolsAndAuthOnly`; it may initialize configured servers but does not change MCP configuration; OAuth requires selecting a server, choosing sign-in, and separately opening the authorization page. Pagination reuses one App Server process across pages. `CodexMcpServerStatusWindow` starts MCP OAuth only on an explicit sign-in action and awaits `mcpServer/oauthLogin/completed`; `CodexMcpServerOAuthLoginWindow` opens the authorization URL only after the user reviews its host and clicks. `Integrations/CodexMcpServerStatusCatalog.cs` parses status and tool metadata; the status window filters by server, tool, auth, state, endpoint and errors, and virtualizes its long list. Search checks fields directly without joining a new aggregate string per keystroke. OAuth sign-in is hidden for non-HTTP transports because the pinned App Server supports this flow only for streamable HTTP servers.
- Manual worktree chats can run a user-confirmed project PowerShell setup script configured in `.codex/codexgui-worktree.json`; setup completion is persisted per chat so failures can be retried. Scheduled automation worktrees do not run this script.
- Project and chat metadata, including CodexGUI-local pin state, is serialized to `%LOCALAPPDATA%\CodexGUI\state.json`; pinned chats render in a separate sidebar group but do not sync to other Codex clients because pinned App Server `0.163.0` has no pin mutation field. Codex App Server persists thread history in the shared Codex home used by the official clients.
- Local `IsArchived` can lag shared Codex history changed by another client. `CodexAppServerClient.ArchiveThreadAsync` reconciles `no rollout found` only after paginated `thread/list` with `archived=true` confirms the exact thread; never treat a missing rollout alone as successful archival.
- `MainWindow.State.cs` validates and recovers `state.json` through `AtomicJsonFile.ReadWithBackup`; saves retain the previous snapshot in `state.json.bak`. `SerializedJsonWriter` writes detached snapshots in order off the UI thread. Queue admission, transition to an active run, worker launch, and completion cleanup await persistence; synchronous callbacks and window shutdown wait for the same queue. Recovery preserves a corrupt primary and repairs it before another save can rotate the backup. If neither snapshot is readable, `_stateSaveBlocked` prevents an empty startup state from overwriting recovery data.
- Named actions can be CodexGUI-local or project-shared in `.codex/codexgui-actions.json`; each entry is either a prompt template or a PowerShell command. `CodexProjectActionStore` validates, revision-checks, and atomically saves the project file. A path-derived named mutex serializes revision checking and replacement across cooperating CodexGUI writers; unrelated external editors do not share that lock. The Actions window filters by name and content, copies actions between scopes without removing the source, and clears the filter after successful create/edit/copy. A command runs only after explicit selection in a terminal scoped to the current thread worktree or project; the existing terminal applies the project access mode and consent.
- When a chat is not selected or CodexGUI lacks focus, completion uses the existing Windows tray icon for a notification; clicking it selects that chat, and its unread marker is persisted in local state.
- `CodexActivityWindow` lists all active, waiting-for-input, and unread chats across projects; `ChatThread.WaitingForInput` is set only while an interactive request or approval dialog is open.
- Local minute-interval, daily/weekly/monthly, and RFC 5545 RRULE automation definitions and reviewable run records are stored under `%LOCALAPPDATA%\CodexGUI\automations`. `MainWindow.xaml.cs` schedules due tasks while the app is open and reconciles detached-worker completion after restart; `Automations/CodexAutomationStore.cs` handles JSON persistence and RFC 5545 recurrence calculations. Schedule definitions retain the previous snapshot in `automations.json.bak`; failed recovery blocks saving until a successful reload. Polling shortens near the next RRULE occurrence to 100 milliseconds. Active run records retain their worker and App Server runtime directories so cleanup cannot remove binaries in use. Automation workers use `approvalPolicy=never` only with the bounded `workspaceWrite` sandbox and sandbox network disabled, and Git projects default to dedicated managed worktrees. A standalone automation can target several projects and creates one run per project. Existing-thread continuation is limited to one project. An automation can optionally resume an existing thread; it preserves that thread's project path or registered worktree and skips while the same thread has another active run. Monthly dates that do not exist in a month are skipped until the next month containing that day. Connected MCP integrations from the shared Codex profile remain available. See `README.md` for the user-facing lifecycle and limitation that scheduled triggers require CodexGUI to remain open.
- Interactive App Server requests are forwarded through the worker's JSONL/control-file contract to `UI/Dialogs/CodexAppServerRequestDialog.cs`; request-id resolution closes any open dialog. Unattended automation workers return empty answers or deny permission/elicitation requests so a background run cannot hang waiting for UI.
- `.github/workflows/release.yml` publishes and prunes releases when `main` receives a push. Work directly on `main`; no additional branches are used.

- `Tests/CodexGUI.Checks.csproj` is the dependency-free regression runner for persistence/recovery, concurrent action writers, schedules, and RPC cancellation/process cleanup. See `README.md` for its command; the release workflow runs it before publishing. Fixtures use temporary paths and fake App Server processes.
