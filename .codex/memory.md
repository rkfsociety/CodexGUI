# CodexGUI working memory

- `App.xaml.cs` handles startup, user installation, single-instance activation, app updates, App Server runtime setup, and first-run ChatGPT device-code login. `AppUpdater.cs` verifies downloaded release archives and signatures.
- `MainWindow.xaml.cs` owns chat/project state, request queues, repository context, and the UI event loop. `Views/WorkspaceView.xaml` is the hot-reloaded layout.
- Normal chat turns and worktree forks run through `CodexAppServerTurnWorker` in a detached CodexGUI child process; file-backed JSONL output and control files under `%LOCALAPPDATA%\CodexGUI\workers\<runId>` preserve reattach, approvals, stop, and steer. Published workers run from a versioned copy under `%LOCALAPPDATA%\CodexGUI\worker-runtimes` so app updates can replace the install directory. `CodexCliWorker.ps1` remains to recover legacy CLI runs saved by older app versions.
- `CodexAppServerClient.cs` starts short-lived app-server processes for request/response calls; `CodexAppServerTurnWorker.cs` handles bidirectional streamed turns and server-initiated requests. Released builds use the downloaded `codex-app-server.exe`; development can fall back to `codex.exe app-server`.
- Released builds download the pinned `codex-app-server` Windows package on first launch; `CodexAppServerRuntime.cs` owns its version, archive digest, extraction checks, and runtime path. Regular chat and app-server calls do not require the Codex CLI package.
- Project and chat metadata is serialized to `%LOCALAPPDATA%\CodexGUI\state.json`; Codex App Server persists thread history in the shared Codex home used by the official clients.
- Local daily/weekly automation definitions and reviewable run records are stored under `%LOCALAPPDATA%\CodexGUI\automations`. `MainWindow.xaml.cs` schedules due tasks while the app is open and reconciles detached-worker completion after restart; `CodexAutomationStore.cs` handles JSON persistence. Active run records retain their worker and App Server runtime directories so cleanup cannot remove binaries in use. Automation workers use `approvalPolicy=never` only with the bounded `workspaceWrite` sandbox and sandbox network disabled, and Git projects default to dedicated managed worktrees. Connected MCP integrations from the shared Codex profile remain available. See `README.md` for the user-facing lifecycle and limitation that scheduled triggers require CodexGUI to remain open.
- `.github/workflows/release.yml` publishes and prunes releases when `main` receives a push. Feature work belongs on a separate branch.
