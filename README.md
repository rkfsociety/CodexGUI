# Codex Desktop

Настольное приложение для Windows, использующее Codex app-server для потоковой работы с задачами в выбранной папке проекта. Окно и список чатов сгруппированы по проектам.

## Запуск

Для разработки нужен .NET 10 SDK. В установленной версии при первом запуске CodexGUI скачивает официальный App Server runtime `0.163.0` и проверяет его SHA-256; отдельная установка Codex CLI для обычной работы не нужна. Если в общем профиле Codex нет авторизации, CodexGUI предложит войти через ChatGPT по коду устройства. Настройки и токены хранятся в общем `%USERPROFILE%\.codex`. CLI используется менеджером маркетплейса плагинов и может понадобиться для восстановления фоновых запусков из старых версий; репозитории и worktree работают через Git. Дважды нажмите `Run-CodexGUI.cmd`. При первом запуске .NET соберёт приложение; далее его можно запускать тем же файлом.

## Релизы и обновления

Релизная версия состоит из трёх числовых частей: `XXX.YYY.ZZZ`. Начальная версия — `0.0.001`; соответствующий тег Git — `v0.0.001`. Push в `main` запускает `.github/workflows/release.yml`: если `<Version>` новее последнего релиза, workflow создаёт соответствующий тег и публикует автономный `CodexGUI.exe` с его SHA-256, а также self-contained архив `CodexGUI-win-x64.zip` с исходным XAML для разработки интерфейса, SHA-256 и подписью манифеста версии и архива. Перед публикацией необходимо настроить GitHub Actions secret `CODEXGUI_RELEASE_SIGNING_PRIVATE_KEY` с закрытым ключом ECDSA P-256 в формате PKCS#8 PEM; соответствующий открытый ключ встроен в `AppUpdater.cs`. При ротации ключа обновите встроенный открытый ключ вместе с Actions secret. Не добавляйте закрытый ключ в репозиторий. После публикации workflow удаляет более старые версионные релизы и теги, оставляя текущую и более новые версии. Для следующего выпуска увеличьте `<Version>` в `CodexGUI.csproj` и отправьте коммит в `main`; тег и релиз создаст workflow. Если версия не изменилась относительно последнего релиза, workflow ничего не публикует.

Для первой установки скачайте и запустите `CodexGUI.exe` из любого места. При первом запуске он устанавливает приложение в `%LOCALAPPDATA%\Programs\CodexGUI`, создаёт ярлык в меню Пуск и запускает установленную копию. После установки исходный EXE можно удалить из «Загрузок». Автономный EXE содержит разметку интерфейса и сценарий обновления. ZIP дополнительно содержит отдельный XAML-файл для редактирования интерфейса на лету. После запуска приложение автоматически проверяет GitHub Releases, а затем повторяет проверку каждые шесть часов. Если доступна новая версия, CodexGUI в фоне скачивает архив и проверяет SHA-256 и подпись; после завершения внизу левой панели появляется маленькая кнопка обновления. Нажмите её, чтобы установить обновление и перезапустить приложение. Проверка и загрузка не блокируют запуск и работу. При ошибке проверка повторится через шесть часов. При тайм-ауте запроса к GitHub приложение повторяет его один раз. Скачивание прерывается, если сервер не передаёт данные 30 секунд; общая длительность загрузки не ограничена этим интервалом. Нажатие на значок трея только открывает окно приложения. Архив проверяется по SHA-256 и подписи манифеста, распаковывается в staging-каталог и заменяет установленную версию с возможностью отката. Не размещайте приложение в `Program Files`: автоматическому обновлению нужна запись в папку установки.

Выберите проект слева. Кнопка `＋` над списком позволяет создать папку нового проекта или добавить существующую. Щёлкните по проекту правой кнопкой и выберите «Убрать из списка», чтобы скрыть его без удаления папки и файлов; повторное добавление той же папки восстановит проект и его чаты. В контекстном меню проекта можно назначить PowerShell-сценарий для подготовки новых ручных worktree: выберите «Настроить подготовку worktree…», укажите `.ps1` внутри папки проекта и сохраните в Git файл `.codex/codexgui-worktree.json` вместе со сценарием. Перед каждым запуском CodexGUI покажет подтверждение; сценарий выполняется с правами текущей учётной записи, его вывод виден в окне подготовки, запуск можно остановить. При отказе запрос продолжится без подготовки. Если сценарий завершится ошибкой, запрос не отправится, а после исправления его можно запустить повторно. Формат `.codex/codexgui-worktree.json` относится к CodexGUI и не заменяет настройки локального окружения официального приложения; пример файла: `{"setupScript":"scripts/setup.ps1"}`. Расписания и другие Codex-клиенты эту настройку не используют. Новые чаты создаются внутри выбранного проекта и продолжаются в той же папке. Щелкните правой кнопкой по чату, чтобы закрепить или открепить его, ответвить его в отдельный чат с копией истории, архивировать или удалить. Закреплённые чаты показываются отдельной группой над недавними; их порядок хранится локально в state.json и не синхронизируется с другими клиентами Codex. Кнопка `Архив` над списком чатов открывает архив; оттуда чат можно восстановить. Кнопка `Активность` показывает чаты, которые выполняются, ждут решения или имеют непрочитанный ответ; выберите запись, чтобы открыть чат. Управление историей выполняется через Codex App Server. Список проектов и чатов сохраняется в `%LOCALAPPDATA%\CodexGUI\state.json`; историю диалогов хранит App Server. В правом верхнем углу области чата отображаются вложения и счётчики `+ / −` для текущего кода относительно общей базы с upstream: учитываются локальные коммиты и незакоммиченные staged/unstaged/untracked изменения, а изменения, уже присутствующие в upstream, не считаются. Если upstream не настроен, используется `origin/HEAD`; когда базу сравнения определить нельзя, счётчики показываются как `—`. Кнопка «Данные» в верхней панели открывает сведения о чате, Git-ветке и синхронизации с upstream, staged, изменённых и новых файлах, ссылке на origin и дереве файлов. Для незакоммиченных изменений доступна команда «Проверить изменения», запускающая Codex App Server reviewer и показывающая его результат. В diff подсвечены изменения, основные токены кода и строки добавления/удаления. Выделите строки, создайте несколько отдельных веток замечаний и ответы к ним, затем добавьте ветки в композер как контекст запроса. Черновики веток существуют в окне reviewer до добавления в запрос. Состояние репозитория обновляется каждые 10 секунд, пока панель открыта. В панели Git можно добавить все изменения или отдельные файлы в индекс, снять их с индекса, создать коммит только из staged-изменений и отправить текущую ветку в настроенный upstream; для новой ветки доступна публикация в origin без force-push. Для чистой, уже отправленной ветки GitHub доступна кнопка «Создать Pull Request»: укажите заголовок и описание, при необходимости отметьте черновик; целевая ветка выбирается по настройке репозитория GitHub. Нужен установленный и авторизованный GitHub CLI (`gh`). Ветка не отправляется автоматически; после создания PR откроется в браузере. Правый щелчок по отслеживаемому файлу открывает восстановление его версии из HEAD после подтверждения. В окне diff текстовых изменений отслеживаемого файла можно выделить строки одного блока: добавить его в индекс, снять staged-блок или отменить незастейдженные изменения этого блока после подтверждения. Для untracked-пути контекстное меню показывает список неигнорируемых файлов, которые Git удалит после подтверждения; ignored- и tracked-файлы сохраняются.

Иконка Codex остаётся в системном трее, пока приложение запущено. Повторный запуск активирует открытое окно вместо запуска второго экземпляра. Сворачивание окна прячет его в трей; щелчок по иконке возвращает окно. В контекстном меню доступны открытие, новый чат и выход. Закрытие окна завершает только оболочку: активный app-server worker продолжает ход, а при следующем запуске интерфейс подключается к нему и восстанавливает очередь и журнал событий.

Кнопка `Терминал` открывает окно с несколькими PowerShell-вкладками в папке текущего чата или проекта. Команды выполняются через App Server `command/exec`. На Windows интерактивный PTY нельзя запустить из workspace sandbox, поэтому в режиме без полного доступа CodexGUI отдельно спрашивает согласие на shell с правами текущей учётной записи Windows вне sandbox. После согласия это ограничение действует для вкладок этого окна; закрытие окна завершает его терминалы. Сейчас доступны обычные команды и текстовый вывод; полноэкранные консольные интерфейсы, например редакторы в терминале, пока не поддерживаются.

Кнопка `Расписания и результаты` открывает локальные автоматизации Codex. Создайте задачу с интервалом в заданное число минут либо с ежедневным, еженедельным или ежемесячным повтором; выберите один или несколько проектов, модель и усилия, а для календарных расписаний — время в локальном часовом поясе. Для сложного графика выберите «Расширенное правило (RRULE)», укажите DTSTART — дату и местное время — и правило RFC 5545; COUNT или UNTIL могут ограничить серию. BYSECOND=60 не поддерживается. Для ежемесячной задачи задаётся число месяца; если такого числа в месяце нет, запуск переносится на следующий месяц, где оно существует. Для нескольких проектов запускается отдельный чат на каждый проект и, если включена изоляция, отдельный worktree. При выборе одного проекта можно продолжать существующий чат: следующие запуски сохраняют его контекст и исходную рабочую папку или зарегистрированный worktree; пока в чате идёт другой запуск, расписание ждёт. Если чат недоступен или архивирован, редактор сохраняет прежний выбор и явно сообщает об этом, а не подменяет его новой сессией. Планировщик запускается вместе с CodexGUI и обычно проверяет расписания каждые 30 секунд; перед ближайшим запуском RRULE интервал опроса сокращается до 100 миллисекунд. Чтобы задачи запускались по расписанию, приложение должно быть открыто. Уже начатая автоматизация работает в отдельном процессе и продолжит ход после закрытия окна. Для новых чатов в Git-проекте включён отдельный worktree, чтобы изменения не попадали прямо в основную рабочую папку. Для автоматических запусков интерактивные подтверждения отключены; команды работают в ограниченном `workspace-write` sandbox с отключённым сетевым доступом. Подключённые MCP-интеграции из профиля Codex при этом остаются доступны. Запросы на пользовательский ввод автоматически получают пустые ответы, а запросы дополнительных разрешений и MCP-подтверждения отменяются, чтобы фоновый процесс не ожидал диалога. Результаты и ошибки сохраняются локально; завершённый чат можно открыть из очереди и отметить проверенным. Если приложение было закрыто в момент запуска, после следующего старта выполняется не более одного пропущенного запуска на расписание.

В композере можно выбрать модель из каталога Codex App Server и поддерживаемый ею уровень усилий; оба значения всегда заданы и сохраняются между запусками. Если сохраненного выбора еще нет, используются GPT-6-Luna и высокие усилия. Кнопка `Действия` открывает локальную библиотеку именованных шаблонов: их можно создать, изменить, удалить и вставить в черновик без отправки запроса. Кнопка `Скриншот` позволяет выделить область экрана, сохранить её в PNG и добавить путь к изображению в запрос Codex. Здесь же отображаются оставшиеся лимиты Codex на 5-часовое и недельное окна со временем сброса; они обновляются при запуске, после запроса и каждые пять минут через `account/rateLimits/read` app-server. Режим по умолчанию — `Попросить подтверждение`: Codex может менять файлы проекта, а для действий за его пределами использует запрос подтверждения (`on-request`). Запросы на запуск команд и изменение файлов показываются в CodexGUI; их можно разрешить один раз, разрешить на время чата или отклонить. Вопросы от инструментов, формы MCP и запросы дополнительных разрешений тоже открываются в CodexGUI. Для разрешений выбираются запрошенные категории доступа и срок действия; по умолчанию они отклонены. MCP-ссылка не открывается автоматически: сначала пользователь нажимает «Открыть ссылку». Режим `Полный доступ` снимает ограничения песочницы и подтверждений; приложение отдельно спрашивает согласие перед его включением. Настроенный в Codex профиль сохраняется. Во время выполнения хода новые сообщения можно поставить в очередь или направить в текущий ход; ход можно остановить. Для отдельной задачи включите в композере режим «Рабочая копия»: новый чат начнётся в изолированном Git worktree. Если чат уже начат, приложение создаст его отдельную копию и ответвит сессию в worktree; исходный чат останется доступен. Выбор хранится отдельно в каждом чате. Кнопка `Цель` и команда `/goal` открывают управление постоянной целью текущего чата: текстом, статусом, необязательным лимитом токенов и прогрессом. Команды `/goal pause`, `/goal resume` и `/goal complete` меняют статус; `/goal clear` удаляет цель после подтверждения. Цель хранится в истории App Server и общая с другими клиентами Codex; задавать её можно после первого запроса в чате.

Завершённые ответы Codex оформляются с заголовками, списками, таблицами, выделением, встроенным и многострочным кодом; ссылки HTTP/HTTPS открываются только после нажатия. Во время генерации текст обновляется без задержки, а форматирование применяется после ответа. Ответ Codex можно скопировать кнопкой в заголовке сообщения. Сообщения в чате разделены отступами и карточками. Между ответами отображается ход работы Codex: доступные сводки размышлений, команды, изменения файлов, вызовы инструментов, субагенты, поиск и план. Записи действий показывают выполнение, завершение или ошибку; раскройте запись, чтобы посмотреть подробности, текст команды и её вывод. Вызов субагента можно открыть отдельным чатом. Кнопка `Субагенты текущего чата` показывает всех получателей multi-agent вызовов, их задания и последнее известное состояние; обновите список после появления новых событий или откройте агента, чтобы читать его полную историю в отдельном чате. Сохраняются все thread ID из `receiverThreadIds`, а не только первый дочерний чат. Отображаются события, которые передаёт app-server; сохранённые действия также восстанавливаются из истории сеанса.

В поле запроса `Ctrl+V` добавляет скопированные в Проводнике файлы (в том числе несколько сразу) в контекст. Скриншот или другое изображение из буфера автоматически сохраняется в PNG в `%LOCALAPPDATA%\CodexGUI\attachments` и добавляется в запрос; эти файлы сохраняются для последующего чтения Codex. Обычный текст вставляется как прежде.

## Плагины и скиллы

Кнопка `Плагины и скиллы` в боковой панели или команда `/plugins` открывает каталог установленного Codex CLI. По умолчанию показаны установленные плагины; снимите флажок `Только установленные`, чтобы искать доступные плагины из настроенных маркетплейсов. Плагины можно устанавливать, включать и отключать. Если сервис требует подключения аккаунта, завершите авторизацию в оригинальном Codex. Названия и идентификаторы каталога передаются CLI; для некоторых удалённых плагинов CLI возвращает только технический идентификатор.

Кнопка `Скиллы` в композере или команда `/skills` открывает все скиллы, обнаруженные Codex для текущего проекта: системные, пользовательские, проектные и из установленных плагинов. Поиск работает по названию, описанию и источнику. `В запрос` добавляет вызов `$имя-скилла`, сохраняя черновик. Imagegen и Computer Use находятся в начале списка. Можно включать и отключать отдельные скиллы. Для установки дополнительных скиллов используйте доступный `skill-installer`.

CodexGUI использует ту же конфигурацию и установленные плагины, что и Codex CLI; отдельные копии скиллов не создаются. Изменения применяются при следующем запуске запроса, включая продолжение чата; уже выполняющиеся запросы продолжают использовать прежнюю конфигурацию. Недоступные по политике плагины установить нельзя. Ошибки загрузки каталогов показываются в окне.

Наличие скилла не гарантирует доступность его инструментов. Imagegen использует встроенный `image_gen` установленного Codex, если он доступен; приложение не подключает платный Images API автоматически. Computer Use на Windows требует runtime Codex, инструмента `node_repl` и пакета `@oai/sky`; разрешения на управление приложениями остаются под управлением Codex. Каталог сам по себе не генерирует изображения и не управляет окнами.

Менеджер использует команды `codex plugin list --available --json`, `codex plugin add` и методы app-server `skills/list`, `skills/config/write`, `config/value/write`. Экспериментальные методы `plugin/list` и `plugin/install`, которые официальная документация не рекомендует для production-клиентов, не используются. См. [плагины Codex](https://learn.chatgpt.com/docs/plugins), [app-server](https://learn.chatgpt.com/docs/app-server) и [Computer Use](https://learn.chatgpt.com/docs/computer-use).

При открытой панели «Данные» в узком окне список проектов и чатов временно скрывается, освобождая место переписке. Закройте панель «Данные», чтобы вернуть список.

## Изменения интерфейса на лету

Выбор папки проекта, setup-сценария или вложения, а также сохранение скриншота выполняются в общем тёмном WPF-пикере. В поле пути можно ввести или вставить адрес папки напрямую.

Визуальная структура находится в `Views/WorkspaceView.xaml`. Пока приложение открыто, сохранение этого файла автоматически перечитывает разметку и обновляет окно без перезапуска. Если разметка временно некорректна, приложение оставляет предыдущую версию экрана и показывает ошибку. Поведение приложения и интеграция с Codex App Server находятся в `MainWindow.xaml.cs`; изменения C# требуют нового запуска.

Чтобы снять PNG-превью без запуска CodexGUI, сначала выполните `dotnet build --no-restore`, затем `pwsh -NoProfile -STA -File Scripts/Capture-WorkspacePreview.ps1`. По умолчанию рендерится `Views/WorkspaceView.xaml` с локальными примерными сообщениями; добавьте `-View Welcome`, чтобы увидеть пустой чат с приветствием и быстрыми действиями. Режимы `-View Calendar`, `-View FilePicker`, `-View FolderPicker` и `-View SavePicker` показывают тёмный календарь и варианты файлового пикера. Для окон активности, действий, Pull Request, редактора расписаний и подготовки worktree укажите `-View Activity`, `-View Actions`, `-View PullRequest`, `-View AutomationEditor` или `-View Setup` — используются демонстрационные данные. Во всех режимах PNG сохраняется в `%TEMP%`; путь и размер можно задать параметрами `-OutputPath`, `-Width` и `-Height`. Режимы `Welcome`, `Activity`, `Actions`, `FilePicker`, `FolderPicker`, `SavePicker`, `AutomationEditor`, `PullRequest` и `Setup` загружают UI-код из сборки в PowerShell и рендерят его без показа окна, старта CodexGUI или App Server.

Приложение не включает отдельную копию модели и не хранит токены. Обычные чаты, обзоры изменений и автоматизации выполняются официальным Codex App Server runtime; устанавливать Codex CLI для них не нужно. CLI используется для управления плагинами и восстановления старых фоновых задач. Иконка приложения находится в `Assets/codex-assistant.png` и `Assets/codex-assistant.ico`.
