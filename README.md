# CodexGUI

Настольный клиент Codex для Windows: чаты по проектам, работа с кодом и Git через официальный Codex App Server.

## Установка

1. Скачайте `CodexGUI.exe` из [последнего релиза](https://github.com/rkfsociety/CodexGUI/releases/latest) и запустите его.
2. Приложение установится в профиль пользователя и скачает App Server при первом запуске.
3. Войдите через ChatGPT, выберите папку проекта и начните чат.

Отдельная установка Codex CLI для чатов не нужна. Обновления загружаются автоматически; для установки нажмите появившуюся кнопку обновления.

## Возможности

- История чатов, поиск, вложения, очередь запросов и цели.
- Выбор модели, управление разрешениями и просмотр работы субагентов.
- Git diff, проверка изменений, коммиты и изолированные worktree.
- Кнопка «Git-контекст в запрос»: вставляет актуальную краткую сводку ветки и изменений в черновик агента (для изолированного чата — из его worktree), не отправляя её автоматически. Локальная проверка предупреждает о конфликтах, detached HEAD, отсутствии upstream и отставании от удалённой ветки; конфликтные файлы выделяются отдельно.
- Git-контекст агента фиксирует исходный SHA коммита HEAD и предупреждает о потенциально чувствительных файлах по именам, не читая их содержимое; управляющие символы безопасно экранируются.
- При вставке Git-контекста агент получает ограниченный список локальных инструкций и файлов сборки/проверок (например, `AGENTS.md`, `*.csproj`, `package.json`), без чтения содержимого и запуска команд.
- Перед коммитом приложение отдельно проверяет имена **реально подготовленных в индексе** файлов и запрашивает подтверждение при обнаружении потенциальных ключей, учётных данных или `.env`.
- Скиллы, плагины, MCP, PowerShell-терминал и повторяемые действия.
- Локальные расписания: для запуска новых задач приложение должно быть открыто.
- Рабочий экран с деревом файлов и картой проекта, карточкой цели, файлами контекста и быстрыми инструментами. Верхняя панель переключает проекты и открывает поиск по коду; вкладка «Чат» в нижней панели открывает историю, «Агент» — субагентов, «Инструменты» — остальные функции, включая усилия модели, worktree и лимиты.
- Дерево раскрывает вложенные папки; двойной щелчок открывает текстовый просмотрщик с прикреплением файла к запросу. «Создать файл» создаёт пустой файл и прикрепляет его к черновику; существующие файлы не перезаписываются. Просмотр ограничен текстовыми файлами до 2 МБ.
- Поиск проверяет имена и содержимое без учёта регистра, показывает номера строк и открывает найденный файл. Исключаются `.git`, `bin`, `obj`, `node_modules`, `.vs`, ссылки, двоичные файлы и содержимое файлов больше 1 МБ. Результат ограничен 200 совпадениями, 5000 файлами и 10000 папками; достижение предела и пропуски обозначаются в окне.
- Карта показывает до шести узлов: папки верхнего уровня, зависимости из `.csproj` / `package.json` в корне и ближайших папках либо группы файлов по расширению на этих двух уровнях. Масштаб, полный вид и переход по узлам работают с текущим проектом или worktree; это обзор, а не полный граф импортов.
- Шаги цели добавляются, отмечаются и удаляются вручную; счётчик и кольцо отражают выполненные шаги. Список сохраняется локально вместе с чатом и не синхронизируется с другими клиентами Codex; сама цель по-прежнему хранится через App Server. «Контекст и память» открывает реальные `AGENTS.md`, `.codex/memory.md`, `.codex/decisions.md` и `README.md`, если они существуют. «Веб-поиск» открывает результаты введённого запроса в системном браузере.

Настройки и история используют общий профиль Codex (`%USERPROFILE%\.codex` или `CODEX_HOME`); состояние приложения хранится в `%LOCALAPPDATA%\CodexGUI`. Для Git нужен установленный Git, для управления плагинами — Codex CLI, для создания Pull Request — GitHub CLI.

## Разработка

Нужен .NET 10 SDK. Запуск из исходников — `Run-CodexGUI.cmd`.

```powershell
dotnet build Build/CodexGUI.csproj --no-restore
dotnet run --project Tests/CodexGUI.Checks.csproj
```

Проверки используют временные файлы и тестовые дочерние процессы; пользовательские чаты и расписания не затрагиваются. Они также запускаются перед публикацией релиза в GitHub CI.

Разметка `Views/WorkspaceView.xaml` обновляется в открытом приложении при сохранении. Изменения C# требуют перезапуска.

При каждом новом релизе workflow составляет описание по коммитам после предыдущей версии. Для точных формулировок коммит может содержать строки `Release-Note-Added:`, `Release-Note-Changed:` и `Release-Note-Fixed:`; без них используются заголовки коммитов.
