# Codex Desktop

Небольшое настольное приложение для Windows, которое запускает установленный Codex CLI в выбранной папке проекта. Окно и список чатов сгруппированы по проектам.

## Запуск

Нужен .NET 10 SDK и установленный Codex CLI с действующим входом. Дважды нажмите `Run-CodexGUI.cmd`. При первом запуске .NET соберёт приложение; далее его можно запускать тем же файлом.

## Релизы и обновления

Релизная версия состоит из трёх числовых частей: `XXX.YYY.ZZZ`. Начальная версия — `0.0.001`; соответствующий тег Git — `v0.0.001`. Push в `main` запускает `.github/workflows/release.yml`: если `<Version>` новее последнего релиза, workflow создаёт соответствующий тег и публикует автономный `CodexGUI.exe` с его SHA-256, а также self-contained архив `CodexGUI-win-x64.zip` с исходным XAML для разработки интерфейса, SHA-256 и подписью манифеста версии и архива. Перед публикацией необходимо настроить GitHub Actions secret `CODEXGUI_RELEASE_SIGNING_PRIVATE_KEY` с закрытым ключом ECDSA P-256 в формате PKCS#8 PEM; соответствующий открытый ключ встроен в `AppUpdater.cs`. При ротации ключа обновите встроенный открытый ключ вместе с Actions secret. Не добавляйте закрытый ключ в репозиторий. После публикации workflow удаляет более старые версионные релизы и теги, оставляя текущую и более новые версии. Для следующего выпуска увеличьте `<Version>` в `CodexGUI.csproj` и отправьте коммит в `main`; тег и релиз создаст workflow. Если версия не изменилась относительно последнего релиза, workflow ничего не публикует.

Для первой установки скачайте и запустите `CodexGUI.exe` из любого места. При первом запуске он устанавливает приложение в `%LOCALAPPDATA%\Programs\CodexGUI`, создаёт ярлык в меню Пуск и запускает установленную копию. После установки исходный EXE можно удалить из «Загрузок». Автономный EXE содержит разметку интерфейса и сценарий обновления. ZIP дополнительно содержит отдельный XAML-файл для редактирования интерфейса на лету. Приложение автоматически проверяет GitHub Releases при запуске и каждые шесть часов. При тайм-ауте запроса к GitHub приложение повторяет его один раз. Скачивание прерывается, если сервер не передаёт данные 30 секунд; общая длительность загрузки не ограничена этим интервалом. Найденное обновление скачивается и проверяется в фоне; уведомление в системном трее сообщает, когда оно готово. Кнопка «Установить v…» в верхней панели приложения запускает установку в фоне и перезапуск. Нажатие на значок трея только открывает окно приложения. Архив проверяется по SHA-256 и подписи манифеста, распаковывается в staging-каталог и заменяет установленную версию с возможностью отката. Не размещайте приложение в `Program Files`: автоматическому обновлению нужна запись в папку установки.

Выберите проект слева. Кнопка `＋` над списком позволяет создать папку нового проекта или добавить существующую. Щёлкните по проекту правой кнопкой и выберите «Убрать из списка», чтобы скрыть его без удаления папки и файлов; повторное добавление той же папки восстановит проект и его чаты. Новые чаты создаются внутри выбранного проекта и продолжаются в той же папке. Щелкните правой кнопкой по чату, чтобы архивировать его или удалить. Кнопка `Архив` над списком чатов открывает архив; оттуда чат можно восстановить. Удаление также удаляет сохраненный сеанс из Codex CLI и требует подтверждения. Список проектов и чатов сохраняется в `%LOCALAPPDATA%\CodexGUI\state.json`; историю диалогов хранит сам Codex CLI. Кнопка «Данные» в верхней панели открывает сведения о чате, Git-ветке и синхронизации с upstream, staged, изменённых и новых файлах, ссылке на origin и дереве файлов; состояние репозитория обновляется каждые 10 секунд, пока панель открыта.

Иконка Codex остаётся в системном трее, пока приложение запущено. Повторный запуск активирует открытое окно вместо запуска второго экземпляра. Сворачивание окна прячет его в трей; щелчок по иконке возвращает окно. В контекстном меню доступны открытие, новый чат и выход. Закрытие окна завершает только оболочку: активная CLI-сессия продолжает работу, а при следующем запуске интерфейс подключается к ней и восстанавливает очередь сообщений.

В композере можно выбрать модель из каталога установленного Codex CLI и поддерживаемый ею уровень усилий; оба значения всегда заданы и сохраняются между запусками. Если сохраненного выбора еще нет, используются GPT-6-Luna и высокие усилия. Кнопка `Скриншот` позволяет выделить область экрана, сохранить её в PNG и добавить путь к изображению в запрос Codex. Здесь же отображаются оставшиеся лимиты Codex на 5-часовое и недельное окна со временем сброса; они обновляются при запуске, после запроса и каждые пять минут через `account/rateLimits/read` app-server. Режим по умолчанию — `Попросить подтверждение`: Codex может менять файлы проекта, а для действий за его пределами использует запрос подтверждения (`on-request`). Режим `Полный доступ` включает опасный флаг CLI без песочницы и подтверждений; приложение отдельно спрашивает согласие перед его включением. Настроенный в Codex профиль сохраняется. Во время выполнения запроса новые сообщения можно отправлять в очередь; очередь сохраняется и обрабатывается после текущего запроса. Для отдельной задачи включите в композере режим «Рабочая копия»: новый чат начнётся в управляемом Git worktree Codex CLI. Если чат уже начат, приложение создаст его отдельную копию и ответвит сессию в worktree; исходный чат останется доступен. Выбор хранится отдельно в каждом чате.

Сообщения в чате разделены отступами и карточками. Между ответами отображается ход работы Codex: доступные сводки размышлений, команды, изменения файлов, вызовы инструментов, поиск и план. Записи действий показывают выполнение, завершение или ошибку; раскройте запись, чтобы посмотреть подробности, текст команды и её вывод. Отображаются только события, которые передаёт Codex CLI; действия также восстанавливаются из истории сеанса.

В поле запроса `Ctrl+V` добавляет скопированные в Проводнике файлы (в том числе несколько сразу) в контекст. Скриншот или другое изображение из буфера автоматически сохраняется в PNG в `%LOCALAPPDATA%\CodexGUI\attachments` и добавляется в запрос; эти файлы сохраняются для последующего чтения Codex. Обычный текст вставляется как прежде.

## Плагины и скиллы

Кнопка `Плагины и скиллы` в боковой панели или команда `/plugins` открывает каталог установленного Codex CLI. По умолчанию показаны установленные плагины; снимите флажок `Только установленные`, чтобы искать доступные плагины из настроенных маркетплейсов. Плагины можно устанавливать, включать и отключать. Если сервис требует подключения аккаунта, завершите авторизацию в оригинальном Codex. Названия и идентификаторы каталога передаются CLI; для некоторых удалённых плагинов CLI возвращает только технический идентификатор.

Кнопка `Скиллы` в композере или команда `/skills` открывает все скиллы, обнаруженные Codex для текущего проекта: системные, пользовательские, проектные и из установленных плагинов. Поиск работает по названию, описанию и источнику. `В запрос` добавляет вызов `$имя-скилла`, сохраняя черновик. Imagegen и Computer Use находятся в начале списка. Можно включать и отключать отдельные скиллы. Для установки дополнительных скиллов используйте доступный `skill-installer`.

CodexGUI использует ту же конфигурацию и установленные плагины, что и Codex CLI; отдельные копии скиллов не создаются. Изменения применяются при следующем запуске запроса, включая продолжение чата; уже выполняющиеся запросы продолжают использовать прежнюю конфигурацию. Недоступные по политике плагины установить нельзя. Ошибки загрузки каталогов показываются в окне.

Наличие скилла не гарантирует доступность его инструментов. Imagegen использует встроенный `image_gen` установленного Codex, если он доступен; приложение не подключает платный Images API автоматически. Computer Use на Windows требует runtime Codex, инструмента `node_repl` и пакета `@oai/sky`; разрешения на управление приложениями остаются под управлением Codex. Каталог сам по себе не генерирует изображения и не управляет окнами.

Менеджер использует команды `codex plugin list --available --json`, `codex plugin add` и методы app-server `skills/list`, `skills/config/write`, `config/value/write`. Экспериментальные методы `plugin/list` и `plugin/install`, которые официальная документация не рекомендует для production-клиентов, не используются. См. [плагины Codex](https://learn.chatgpt.com/docs/plugins), [app-server](https://learn.chatgpt.com/docs/app-server) и [Computer Use](https://learn.chatgpt.com/docs/computer-use).

При открытой панели «Данные» в узком окне список проектов и чатов временно скрывается, освобождая место переписке. Закройте панель «Данные», чтобы вернуть список.

## Изменения интерфейса на лету

Визуальная структура находится в `Views/WorkspaceView.xaml`. Пока приложение открыто, сохранение этого файла автоматически перечитывает разметку и обновляет окно без перезапуска. Если разметка временно некорректна, приложение оставляет предыдущую версию экрана и показывает ошибку. Поведение приложения и интеграция с CLI находятся в `MainWindow.xaml.cs`; изменения C# требуют нового запуска.

Приложение не включает отдельную копию модели и не хранит токены. Запросы передаются установленному `codex` CLI. Иконка приложения находится в `Assets/codex-assistant.png` и `Assets/codex-assistant.ico`.
