# CodexGUI

Настольный клиент Codex для Windows: чаты по проектам, работа с кодом и Git через официальный Codex App Server.

## Установка

1. Скачайте `CodexGUI.exe` из [последнего релиза](https://github.com/rkfsociety/CodexGUI/releases/latest) и запустите его.
2. Приложение установится в профиль пользователя и скачает App Server при первом запуске.
3. Войдите через ChatGPT, выберите папку проекта и начните чат.

Все сборки приложения self-contained для Windows x64 и не требуют установленного .NET Desktop Runtime. Результат `dotnet build` — многофайловая сборка; сохраняйте её DLL и runtime-файлы рядом с EXE. `Run-CodexGUI.cmd` публикует и запускает portable single-file EXE.

Отдельная установка Codex CLI для чатов не нужна. Обновления загружаются автоматически; для установки нажмите появившуюся кнопку обновления.

## Возможности

- История чатов, поиск, вложения, очередь запросов и цели.
- Выбор модели, управление разрешениями и просмотр работы субагентов.
- Git diff, проверка изменений, коммиты и изолированные worktree.
- Кнопка «Git-контекст в запрос»: вставляет актуальную краткую сводку ветки и изменений в черновик агента (для изолированного чата — из его worktree), не отправляя её автоматически. Локальная проверка предупреждает о конфликтах, detached HEAD, отсутствии upstream и отставании от удалённой ветки; конфликтные файлы выделяются отдельно.
- Git-контекст агента фиксирует исходный SHA коммита HEAD и предупреждает о потенциально чувствительных файлах по именам, не читая их содержимое; управляющие символы безопасно экранируются.
- При вставке Git-контекста агент получает ограниченный список локальных инструкций и файлов сборки/проверок (например, `AGENTS.md`, `*.csproj`, `package.json`), без чтения содержимого и запуска команд.
- Перед коммитом приложение отдельно проверяет имена **реально подготовленных в индексе** файлов и запрашивает подтверждение при обнаружении потенциальных ключей, учётных данных или `.env`.
- Скиллы, плагины, MCP, PowerShell-терминал и повторяемые действия.
- Встроенный браузер на Microsoft Edge WebView2: вкладки, переходы назад/вперёд, адресная строка и поиск. Окно CodexGUI можно открыть для управления через ChatGPT Computer Use (`@computer-use`), если плагин включён и доступ к приложению разрешён. Браузер хранит отдельный профиль в `%LOCALAPPDATA%\CodexGUI\browser`; в Windows должен быть установлен WebView2 Runtime.
- Локальные расписания: для запуска новых задач приложение должно быть открыто.
- Рабочий экран с деревом файлов и картой проекта, карточкой цели, файлами контекста и быстрыми инструментами. Верхняя панель переключает проекты и открывает поиск по коду (Ctrl+K); Ctrl+N создаёт новый чат, Ctrl+F ищет по чатам; вкладка «Чат» в нижней панели открывает историю, «Агент» — субагентов, «Инструменты» — остальные функции, включая усилия модели, worktree и лимиты.
- Дерево раскрывает вложенные папки; двойной щелчок открывает текстовый просмотрщик с прикреплением файла к запросу. «Создать файл» создаёт пустой файл и прикрепляет его к черновику; существующие файлы не перезаписываются. Просмотр ограничен текстовыми файлами до 2 МБ.
- Поиск проверяет имена и содержимое без учёта регистра, показывает номера строк и открывает найденный файл. Исключаются `.git`, `bin`, `obj`, `node_modules`, `.vs`, ссылки, двоичные файлы и содержимое файлов больше 1 МБ. Результат ограничен 200 совпадениями, 5000 файлами и 10000 папками; достижение предела и пропуски обозначаются в окне.
- Карта показывает до шести узлов: папки верхнего уровня, зависимости из `.csproj` / `package.json` в корне и ближайших папках либо группы файлов по расширению на этих двух уровнях. Масштаб, полный вид и переход по узлам работают с текущим проектом или worktree; это обзор, а не полный граф импортов.
- Шаги цели добавляются, отмечаются и удаляются вручную; счётчик и кольцо отражают выполненные шаги. Список сохраняется локально вместе с чатом и не синхронизируется с другими клиентами Codex; сама цель по-прежнему хранится через App Server. «Контекст и память» показывает недавние чаты проекта с переходом в историю; свободные строки занимают реальные `AGENTS.md`, `.codex/memory.md`, `.codex/decisions.md` и `README.md`. Кнопка «Все» открывает историю или файлы контекста. Время последней активности сохраняется при завершении хода; для старых записей без этой даты показывается «Чат». «Веб-поиск» открывает результаты введённого запроса в системном браузере.

Настройки и история используют общий профиль Codex (`%USERPROFILE%\.codex` или `CODEX_HOME`); состояние приложения хранится в `%LOCALAPPDATA%\CodexGUI`. Для Git нужен установленный Git, для управления плагинами — Codex CLI, для создания Pull Request — GitHub CLI.

## Разработка

Нужен .NET 10 SDK. Запуск из исходников — `Run-CodexGUI.cmd`.

```powershell
dotnet build Build/CodexGUI.csproj --no-restore
dotnet build Tests/CodexGUI.Checks.csproj --no-restore
```

Запуск тестового EXE и проверка запуска приложения выполняются в GitHub Actions; локально используйте только сборку.

Автономный `.exe` для запуска или передачи на другую машину:

```powershell
dotnet publish Build/CodexGUI.csproj -p:PublishProfile=Portable
```

Готовый файл: `Build/bin/Portable/CodexGUI.exe`. Профиль использует тот же self-contained single-file формат, что и релизный workflow; runtime уже внутри файла. Smoke-проверка запускает `.exe` и выполняется только в GitHub Actions; локально используйте `dotnet build` и не запускайте `Scripts/Test-PortablePackage.ps1`.

Проверки используют временные файлы и тестовые дочерние процессы; пользовательские чаты и расписания не затрагиваются. Они также запускаются перед публикацией релиза в GitHub CI.

Разметка `Views/WorkspaceView.xaml` обновляется в открытом приложении при сохранении. Изменения C# требуют перезапуска.

Фон рабочего пространства встроен в сборку (`Assets/Workspace/terrain.png`); центральная сцена, карта, меню и элементы ввода остаются интерактивными WPF-контролами. Браузерный runtime для оформления не требуется.

Сравнение с референсом без запуска App Server и чтения пользовательских чатов:

```powershell
pwsh -NoProfile -STA -File Scripts/Capture-WorkspacePreview.ps1 -View Reference -Width 1585 -Height 992 -VerifyLayout
```

Для локальной диагностики координат композера используйте `-ReportLayout`: скрипт выводит JSON с границами и видимостью элементов, не открывая окно CodexGUI. Например, проверка границ адаптивной панели лимитов:

```powershell
pwsh -NoProfile -STA -File Scripts/Capture-WorkspacePreview.ps1 -View Workspace -Width 1449 -Height 850 -ReportLayout
pwsh -NoProfile -STA -File Scripts/Capture-WorkspacePreview.ps1 -View Workspace -Width 1450 -Height 850 -ReportLayout
```

`Reference` использует только тестовые данные из `Scripts/WorkspaceReferenceFixture.ps1`. Проверка сравнивает координаты и размеры панелей с допуском 2 пикселя, а также проверяет границы элементов ввода и отсутствие обрезания текста карточек. Для пустого приветственного экрана используйте `-View Reference`, для примера переписки — `-View Workspace`; уменьшенный размер окна можно проверить с `-Width 900 -Height 620`. Состояния композера проверяются параметром `-ComposerState Draft`, `Attachments`, `Queued` или `Running`; без него используется пустой ввод. Все состояния — локальные визуальные фикстуры, запросы не отправляются.

Для быстрого снимка интерфейса из текущего исходного кода, не запуская CodexGUI:

```powershell
pwsh -NoProfile -File Scripts/Capture-CurrentInterface.ps1
pwsh -NoProfile -File Scripts/Capture-CurrentInterface.ps1 -View Reference -VerifyLayout
```

Скрипт запускает только скрытый STA-процесс PowerShell для WPF-рендера: окно не появляется, фокус не меняется, CodexGUI не запускается. По умолчанию рендерится текущая разметка с дизайн-фикстурой референса и проверяются её контрольные координаты. PNG сохраняется как `%TEMP%\CodexGUI-current.png`; `-View Workspace` рендерит ту же разметку с примером переписки.

При каждом новом релизе workflow собирает русское описание из `Release-Note-Added:`, `Release-Note-Changed:` и `Release-Note-Fixed:` в телах коммитов после предыдущей версии. Каждый коммит с изменениями приложения должен содержать хотя бы одну такую строку на русском языке; без неё публикация остановится. Коммиты только с документацией, тестами, CI или повышением версии пропускаются.
